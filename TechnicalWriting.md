### 1. Project Objective and Mechanism

The primary goal of the Aether NIHDE project is to solve the dilemma of **speed versus entropy quality** often faced by software-based PRNGs.

**Mechanism Summary:**

1.  **Chaotic Core (Rössler System):** The project uses the Rössler chaotic dynamics  for its superior stability, deliberately avoiding the degeneracy pitfalls of the conventional Lorenz system. The system uses stable parameters ($a=0.1, b=0.1, c=14.0$) to minimize the risk of fixed-point decay due to floating-point precision issues.

2.  **Speed Optimization (Rust Integration):** The numerical integration of the Rössler equations is implemented in Rust. By using a highly optimized core that executes $N=50$ iterations per output byte, the latency is brought down to a final speed of **0.83 µs**—a **11.08x** performance increase.

#### 📐 Mathematical Formulation (Rössler System)

The chaotic behavior is governed by the following set of three coupled, non-linear ordinary differential equations (Rössler Attractor):

$$
\frac{dx}{dt} = -y - z \\
\frac{dy}{dt} = x + ay \\
\frac{dz}{dt} = b + z(x - c)
$$

The system's state variables $(x, y, z)$ are evolved numerically using the **Euler method** (or a similar low-cost integration scheme) over a discrete time step $\Delta t = 0.01$. The next state $(x_{n+1}, y_{n+1}, z_{n+1})$ is calculated after each step:

$$
x_{n+1} = x_n + \Delta t \cdot (-y_n - z_n) \\
y_{n+1} = y_n + \Delta t \cdot (x_n + a y_n) \\
z_{n+1} = z_n + \Delta t \cdot (b + z_n(x_n - c))
$$

For stability and performance, the fixed parameters are set as: $a=0.1, b=0.1, c=14.0$. The iterative update is performed $N=50$ times per output byte to ensure sufficient state diffusion. 

#### 3. Cryptographic Mixing

The system's deterministically evolved state $(x, y, z)$ is converted into a high-entropy byte through two layers of mixing:
* **Level 1 (Rust):** The state is hashed via **SHA-256**. The output byte is derived from the XOR of the first two bytes of the hash digest ($B_0 \oplus B_1$).
* **Level 2 (Python):** The final output is XORed with the previously generated byte (`final_output = current_byte \oplus last_byte`) to break any sequential patterns and guarantee the final **7.7579 bit** quality.
